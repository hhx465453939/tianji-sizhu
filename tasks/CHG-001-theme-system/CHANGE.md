# CHG-001 · 明暗双主题设计系统

**变更编号**: CHG-001
**提出日期**: 2026-10-22
**类型**: 跨层视觉重构（设计系统 + 前端渲染 + 原生窗口外观）
**影响面**: `frontend/src/style.css`、`frontend/tailwind.config.js`、全部页面与组件、`main.go` 窗口背景

---

## 1. 动机

项目当前只有单一深色主题（玄底 + 羊皮纸字），视觉基调偏"夜观星象"。这带来三个实际问题：

1. **默认观感门槛高**：命理工具的高频使用场景是白天、明亮室内、办公环境，深色底在强光下反光严重、可读性下降。
2. **双主题缺失导致品牌表达单一**：国风审美不止"暗夜玄色"，"宣纸晨光"才是文人命理的主流语境。
3. **移动端将来临**（见 CHG-002）：小屏 + 深色 + 高密度数据是本项目最容易翻车的组合，必须在适配前把亮色体系建立起来。

## 2. 目标

- **明亮主题作为默认画面**，暗色主题作为可切换选项（用户偏好持久化）
- 建立**一套完整的设计 token 体系**，使未来新增界面无需再碰颜色硬编码
- 两套主题在**同一组件树上逐像素对位**：布局零位移，仅色彩/光影/描边差异
- 顺带修复响应式缺口（移动端多列挤压），为 CHG-002 铺路
- 保留并强化国风美术基因，不降级为"通用后台管理风"

## 3. 非目标

- 不重写业务逻辑、不改排盘算法、不动 SQLite/Go 数据层
- 不引入 UI 组件库（继续 Tailwind + 原生元素）
- 不做第三主题（预留扩展点，不实现）
- 不改 PDF/打印/导出格式

## 4. 范围

| 层 | 落点 |
|----|------|
| Design token | `frontend/src/style.css`（`[data-theme]` 变量块） |
| Tailwind 映射 | `frontend/tailwind.config.js`（颜色指向 rgb 通道变量） |
| 主题运行时 | `frontend/src/lib/theme/`（读写、初始化、Wails 窗口同步） |
| 切换 UI | 导航栏快捷切换 + 设置页主题卡片 |
| 图表 | `FiveElementRadar.tsx` 颜色改读 token |
| 布局 | 全部页面/组件的 `sm/md/lg` 断点补齐 |
| 原生 | `main.go` `BackgroundColour` 跟随默认亮色，避免启动闪黑 |

## 5. 验收口径

- 首屏无主题闪烁（FOUC），`localStorage` 恢复正确
- 正文对比度 ≥ 4.5:1，大字/图标 ≥ 3:1（WCAG AA）
- 桌面 1280×800 与移动 390×844 两视口，明/暗各一张截图，无遮挡、无溢出、无颜色错位
- 所有既有测试通过（`pnpm test`），`tsc` 零错误
